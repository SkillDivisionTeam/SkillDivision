## 2. Спецификации на входы

Раздел регламентирует входные данные и устройства взаимодействия, необходимые для тестирования системы Skill Division.

**Аппаратные интерфейсы (Входы):**

- **Клавиатура и мышь:** для ввода текстовых данных и навигации в веб-интерфейсе (панель организатора/HR).
- **Сенсорный экран:** для взаимодействия с Telegram-ботом на мобильных устройствах.

**Программные интерфейсы и данные:**

**Учетные данные пользователей:**

- Telegram ID (автоматически передаётся клиентом Telegram).
- Логин/Пароль для веб-интерфейса (формат: `string`/`string`).

**Данные мероприятий:**

| Параметр | Тип | Ограничение |
| -------- | --- | ----------- |
| Название | `string` | max 200 chars |
| Описание | `text` | — |
| Код доступа | `string` | unique |
| Дата проведения | `date` | — |

**Команды Telegram-бота:**

- Текстовые команды: `/start`, `🎮 Играть`.
- Нажатия на инлайн-кнопки (Callback queries): `ans_0`, `duel_1`.

**Внешние API:**

- Ответы от LLM (GigaChat) для генерации вопросов (формат JSON).

**Конфигурационные файлы:**

- Файл `.env` с переменными окружения (токены API, доступы к БД).

## 3. Спецификации на выходы

Раздел регламентирует ожидаемые результаты работы системы после выполнения тестовых сценариев.

**Визуальные выходы (UI):**

- **Telegram-бот:** текстовые сообщения с поддержкой HTML-разметки (блоки кода), меню с кнопками, уведомления о результатах.
- **Веб-интерфейс:** дашборд с графиками, списки мероприятий, всплывающие уведомления.

**Файловые выходы:**

- **Отчёты:** файлы формата `.csv`, содержащие список участников и их результаты.
- **Логи:** системные логи контейнеров Docker (stdout/stderr).

**Сетевые выходы:**

- **HTTP-ответы:** статус-коды (`200 OK`, `201 Created`, `400 Bad Request`, `403 Forbidden`) и JSON-тела ответов от REST API.

**Данные в БД:**

- Новые записи в таблицах `auth_user`, `api_profile`, `api_event`, `api_quizresult` базы данных PostgreSQL.

## 4. Среда тестирования

**Аппаратное обеспечение:**

| Компонент | Требования |
| --------- | ---------- |
| Персональный компьютер | CPU Intel Core i5 / AMD Ryzen 5, RAM 16 GB, SSD 512 GB |
| Мобильное устройство | Смартфон с Android 10+ или iOS 14+ |

**Программное окружение:**

| Компонент | Версия / Описание |
| --------- | ----------------- |
| ОС | Windows 10/11 (с WSL2), Linux Ubuntu 22.04 или macOS |
| Платформа контейнеризации | Docker Engine (v20.10+), Docker Compose (v2.15+) |
| Браузеры | Google Chrome (последняя стабильная версия), Microsoft Edge |
| Клиент Telegram | Официальный Desktop-клиент и мобильное приложение |
| СУБД | PostgreSQL 15 (запущена в контейнере) |
| Backend | Python 3.11, Django (в контейнере) |
| Инструменты тестирования API | Postman / Browser DevTools |

## 5. Специальные требования

1. **Сетевое подключение:** обязательно (связь с Telegram API и GigaChat).
2. **Подготовка БД:** миграции применены, создан суперпользователь.
3. **Учетные записи Telegram:** минимум два аккаунта для тестирования PvP-дуэлей.

## 6. Взаимозависимости

- **Зависимость от Backend:** веб-интерфейс и бот не работают без запущенного контейнера `backend`.
- **Зависимость от Telegram API:** при недоступности серверов Telegram тесты бота невозможны.

## 7. Тесты

### 7.1. Тест 1: Регистрация и профиль (Telegram-бот)

**Свойство A: Первичная регистрация (`/start`)**

| Параметр | Значение |
| -------- | -------- |
| **Вход** | Отправка команды `/start` новым пользователем |
| **Ожидаемое** | Создание записей в `auth_user` и `api_profile`. Ответ бота с Главным меню |
| **Метрика** | Время ответа < 2 сек |

**Свойство B: Просмотр профиля**

| Параметр | Значение |
| -------- | -------- |
| **Вход** | Нажатие кнопки «👤 Мой профиль» |
| **Ожидаемое** | Сообщение содержит актуальные данные (Никнейм, Игр сыграно, Всего очков), полученные по API |

### 7.2. Тест 2: Управление мероприятием (Веб-интерфейс)

**Свойство A: Авторизация**

| Параметр | Значение |
| -------- | -------- |
| **Вход** | Ввод логина/пароля на странице `/login` |
| **Ожидаемое** | Ответ API с токеном (`token`), сохранение в LocalStorage, редирект на `/events` |

**Свойство B: Создание мероприятия**

| Параметр | Значение |
| -------- | -------- |
| **Вход** | Заполнение формы создания (Название, Код, Дата) |
| **Ожидаемое** | Новая карточка мероприятия в списке. Доступность мероприятия для бота |

### 7.3. Тест 3: Игровая механика (Telegram-бот)

**Свойство A: Одиночный режим**

| Параметр | Значение |
| -------- | -------- |
| **Вход** | Выбор «🎮 Играть» → «👤 Одиночная» |
| **Ожидаемое** | Бот присылает вопросы последовательно. Форматирование кода (тег `<pre>`) отображается корректно |

**Свойство B: Начисление очков**

| Параметр | Значение |
| -------- | -------- |
| **Вход** | Нажатие верного варианта ответа |
| **Ожидаемое** | Сообщение «Верно!». В конце игры — отправка результата (`POST /api/submit-score/`) на сервер |

### 7.4. Тест 4: Аналитика и отчетность (Веб-интерфейс)

**Свойство A: Дашборд мероприятия**

| Параметр | Значение |
| -------- | -------- |
| **Вход** | Переход на страницу деталей мероприятия |
| **Ожидаемое** | Графики обновляются. Счётчик «Активных участников» соответствует реальности |

**Свойство B: Таблица лидеров**

| Параметр | Значение |
| -------- | -------- |
| **Вход** | Просмотр списка лидеров на странице |
| **Ожидаемое** | Отображение имени пользователя и его максимального балла, отсортированное по убыванию |

### 7.5. Тест 5: Модульное тестирование (Unit Tests)

#### Сценарий 5.1: Калькулятор очков (Bot Logic)

**Цель:** проверка начисления баллов.

| Вход | Ожидаемое |
| ---- | --------- |
| Правильный ответ | `score += 5` |
| Неправильный ответ | Очки не изменяются |

#### Сценарий 5.2: Валидация данных мероприятия (Django Models)

**Цель:** проверка уникальности кода мероприятия.

| Вход | Ожидаемое |
| ---- | --------- |
| Создание `Event` с уже существующим `event_code` | Ошибка БД `IntegrityError` или валидации сериализатора |
| Создание `Event` без названия | Ошибка обязательного поля |

#### Сценарий 5.3: Парсер ответов ИИ (Bot Utils)

**Цель:** проверка очистки JSON от GigaChat.

| Параметр | Значение |
| -------- | -------- |
| **Вход** | Строка с Markdown: ````json {"q": "text"}```` |
| **Ожидаемое** | Функция `re` извлекает чистый JSON-объект |

#### Сценарий 5.4: Очередь дуэлей (Bot Memory)

**Цель:** проверка логики подбора соперников.

| Вход | Ожидаемое |
| ---- | --------- |
| Добавление `User_A` в `quick_queue` | Очередь содержит 1 элемент, матч не создан |
| Добавление `User_B` | Очередь очищается, создаётся комната `rooms[duel_A_B]` |

#### Сценарий 5.5: Права доступа (DRF Permissions)

**Цель:** защита API.

| Параметр | Значение |
| -------- | -------- |
| **Вход** | Запрос к защищённому эндпоинту без заголовка `Authorization` |
| **Ожидаемое** | Статус `401 Unauthorized` |
